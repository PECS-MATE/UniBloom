# UniBloom 초기 진행안

상태: 제안. UniBloom 저장소는 GitHub 연결에서 404가 반환되어 확인하지 못했다.
기준: 현재 PECS MATE README와 frontend/package.json. 구현 품질 전체를 검증한 결과는 아니다.

## 방향

기존 React/Vite, FastAPI, MongoDB 기반을 우선 유지한다. 새 기술 도입보다 대상 사용자와 핵심 사용 흐름을 먼저 정한다. 기본 가정은 기존 AAC 사용자를 위한 웹 서비스의 후속 버전이다.

첫 버전의 제안 흐름은 보호자가 카드판을 준비하고, 사용자가 카드를 선택해 음성으로 표현하고, 다음 방문에도 같은 카드 배치를 사용하는 것이다. 기존 의사소통 흐름을 보존하면서 사용 편의성을 개선한다. AI 확장, RFID 확대, 기관 관리 확대는 후속 범위 후보로 둔다.

## 저장소 시작 방식

UniBloom이 비어 있고 같은 제품 계보라면 Git 이력을 보존하는 이전을 권장한다. 이미 작업이 있다면 양쪽 구조와 이력을 확인한 뒤 통합 방식을 정한다. 대상 상태 확인 전에는 덮어쓰기나 강제 푸시를 하지 않는다. .env, 업로드 사진, DB 데이터, 음성 캐시, 로컬 백업은 이전 대상에서 제외한다. 이미지·폰트·모델의 사용 조건도 확인한다.

## 첫 개선 후보

1. 카드 선택부터 발화까지의 사용 흐름과 접근성 개선.
2. 보호자의 카드판 준비 및 사용자별 설정 단순화.
3. 실제 외부 사용을 목표로 할 경우 배포, HTTPS, 계정 및 데이터 보관 방식 정리.

일정과 배포 구성은 팀 규모, 서비스 대상, 사용 기기를 확인한 뒤 확정한다.
